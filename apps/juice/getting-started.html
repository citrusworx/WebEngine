Honest Beta · six steps

Get Juice on a page, then compose in markup.

Juice is a CSS-first, attribute-driven styling system — not a behavior framework. Import core, import a theme, set theme="…", and write structure as attributes. Emerging runtimes are optional extras when you import the JS entry.

What to use first

The same six-step flow as docs/juice/juice-getting-started.md. This page stays short; the docs tree is still the source of truth.

1

Install

Add the published package with the CLI you already use — npm, pnpm, yarn, or bun — consume the workspace package in this monorepo, or skip a bundler and load dist/ from jsDelivr (CDN tab). 

npm install @citrusworx/juiceui
pnpm add @citrusworx/juiceui
yarn add @citrusworx/juiceui
bun add @citrusworx/juiceui
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@citrusworx/juiceui@0.8.0/dist/index.css" />
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@citrusworx/juiceui@0.8.0/dist/themes/kiwipress.css" />
<script type="module" src="https://cdn.jsdelivr.net/npm/@citrusworx/juiceui@0.8.0/dist/index.js"></script>

There is no first-party Juice CDN. jsDelivr (and unpkg) serve the published npm files. Pin @0.8.0. The JS module is optional — it auto-enhances Emerging runtimes. Core plus a theme is enough for CSS-first pages. You can also copy dist/index.css and dist/themes/kiwipress.css next to your HTML.

2

Import core CSS

Core is structure only. No theme identity ships in this file.

import "@citrusworx/juiceui/styles";
3

Import a theme

Library themes: kiwipress, tide, citrusmint, aquaflux. Then set theme="…" on the root. 

import "@citrusworx/juiceui/styles/themes/kiwipress";
4

Compose in markup

Use stack, row, grid, gap, and hooks like hero, card, and panel.

5

App CSS last

Add app selectors only where brand-specific polish is truly needed. Do not wait on config to start.

6

JS is optional

Importing @citrusworx/juiceui auto-enhances Emerging runtimes. Use Sig.js for app state. Neither is required for CSS-first composition.

A first page, live

Import core, import a theme, set theme="…". Then compose with hero, card, and panel. Switch the face — this example wears the active theme. No named app surfaces; those belong to generated product themes. 

import "@citrusworx/juiceui/styles";
import "@citrusworx/juiceui/styles/themes/kiwipress";
import "@citrusworx/juiceui";
<body theme="kiwipress">…</body>

Publishing

Attribute-first UI with theme-owned identity

Juice keeps layout in markup. The theme defines type, color, and surface tone.

Structure

Use stack, row, grid, gap, and spacing attributes first.

Identity

This panel wears the library theme you selected above — KiwiPress, Tide, Citrusmint, or Aquaflux. 

<main stack gap="2rem">
  <section hero padding="2rem" stack gap="1rem">
    <p>Publishing</p>
    <h1>Attribute-first UI with theme-owned identity</h1>
    <p>Juice keeps layout in markup. The theme defines type, color, and surface tone.</p>
  </section>

  <section grid="2x1" gap="1rem">
    <article card padding="1.25rem" stack gap="0.75rem">
      <h2>Structure</h2>
      <p>Use stack, row, grid, gap, and spacing attributes first.</p>
    </article>
    <aside panel padding="1.25rem" stack gap="0.75rem">
      <h2>Identity</h2>
      <p>Use the theme for typography, colors, and semantic defaults.</p>
    </aside>
  </section>
</main>

The mental model

Juice attributes control structure. Theme CSS controls identity. App CSS handles small exceptions. Sig.js or app code handles behavior.

Let Juice own structure

Do not wait on config. Library themes are enough to start. App-owned theme generation is there when a product needs a real brand system.

Depth stays in docs/juice
