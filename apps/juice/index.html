Write structure in markup.

Juice attributes name the job: a column, a row, a stage, a surface. You read the page the way you read HTML — not as a string of utilities, and not as a pile of one-off class names.

Class-heavy CSS

A competent utility layout. Readable if you know the dialect. The structure is still encoded as CSS class names. 

<section class="flex flex-col gap-4 p-8">
  <h2 class="text-2xl font-semibold">Harbor Press</h2>
  <p class="text-base text-slate-600">
    Short-run books and a catalog that still fits on one shelf.
  </p>

Attributes with intent

Same layout job. The markup says stack, gap, grid, and card — the structure you mean. 

<section stack gap="1" padding="2rem">
  <h2>Harbor Press</h2>
  <p>
    Short-run books and a catalog that still fits on one shelf.
  </p>
  <div grid="2x1" gap="1">
    <article card padding="1.25rem" stack gap="0.75rem">
      <h3>The Inlet</h3>
      <p>Essays on harbors and tide tables.</p>
    </article>
    <article card padding="1.25rem" stack gap="0.75rem">
      <h3>Letterpress Hours</h3>
      <p>A shop diary from a one-room bindery.</p>
    </article>
  </div>
</section>

Portable structure

stack, row, grid, and gap are a shared language. Take the same composition across products instead of reinventing layout in each codebase.

Themeable identity

Type, color, and surface tone live in the theme. Swap theme="…" and the page keeps its structure. Juice owns the skeleton; the face is not baked in.

Works with your stack

Vanilla HTML, Vite, Sig.js, or whatever you already ship. Juice is a stylesheet plus attributes — not a React runtime and not a component framework you have to buy into.

Themes own identity.

The sample above is the same markup under every face. Juice keeps layout, spacing, and composition. KiwiPress, Tide, Citrusmint, and Aquaflux decide how that language should feel.

Structure stays in Juice

Layout primitives, spacing, page hooks, and the composition vocabulary do not change when you restyle. This landing is mostly attributes.

Identity stays in the theme

Typography voice, color relationships, and semantic defaults live in the theme CSS. Core has no theme rules. Activate a face with one attribute.

Honest Beta. Strong enough to adopt.

Juice Beta is a CSS-first, attribute-driven styling and composition system — layout, tokens, typography, icons, and page structure, with a documented theme contract. Use it for structure today. Do not wait on a finished component library.

Stable-ish

The reason to start

Attribute-driven styling, layout primitives (stack, row, grid, gap), spacing, color tokens, typography, and icons. This is the core identity of Juice, and it already works in real markup.

Emerging

Useful, still settling

Cards, buttons, forms, nav, bundled themes, and the JS entry are present and documented — APIs can still move. Config-driven branding is Draft. Juice is not a mature component framework and does not pretend to be one.

Runtimes are optional power.

Importing @citrusworx/juiceui auto-enhances valid markup — navigation, disclosure, dialogs, and form and status controls. That is a bonus on top of CSS-first composition, not the reason to adopt Juice. Those runtimes are Emerging.

Install Juice. Compose a page.

npm install @citrusworx/juiceui
pnpm add @citrusworx/juiceui
yarn add @citrusworx/juiceui
bun add @citrusworx/juiceui
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@citrusworx/juiceui@0.9.0/dist/index.css" />
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@citrusworx/juiceui@0.9.0/dist/themes/kiwipress.css" />
<script type="module" src="https://cdn.jsdelivr.net/npm/@citrusworx/juiceui@0.9.0/dist/index.js"></script>

Then import core, import a theme, set theme="…", and write structure as attributes. No bundler? The CDN tab loads published dist/ files from jsDelivr — there is no first-party Juice CDN.
