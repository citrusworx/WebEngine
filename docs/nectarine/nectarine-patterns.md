# Nectarine Patterns

Reusable data patterns built from current Nectarine primitives. **These are not new APIs.** They are recommended compositions you can copy and adapt.

Each pattern follows the same general rules:

- YAML owns table shape, query intent, and HTTP names
- `parser` owns lookup
- app code owns compile
- adapters own sockets
- Seltzer (or Express) owns the listener

Related:

- [Tutorial](./nectarine-tutorial.md) — these patterns composed into one catalog

## Named query lookup

Use this when you want a single intent object by resource, verb, and name.

```ts
import { parser } from "@citrusworx/nectarine";

const spec = parser.genSQL("./models/user/queries.yml", "user", "get", "UserById");
```

The file must nest `user.get.UserById`. If lookup throws, the keys are wrong — not the adapter.

## Operator allow-list SELECT

Use this when compiling the Postgres DSL. Identifiers from YAML; values in `params`.

```ts
const OPS: Record<string, string> = {
  eq: "=",
  neq: "!=",
  gt: ">",
  gte: ">=",
  lt: "<",
  lte: "<=",
};

function buildSelect(spec: {
  select?: string | string[];
  from?: string;
  where?: { column: string; operator: string; value: string };
}): string {
  const fields = Array.isArray(spec.select) ? spec.select.join(", ") : spec.select ?? "*";
  const table = spec.from;
  if (!spec.where) return `SELECT ${fields} FROM ${table}`;
  const op = OPS[spec.where.operator];
  if (!op) throw new Error(`Unknown operator: ${spec.where.operator}`);
  return `SELECT ${fields} FROM ${table} WHERE ${spec.where.column} ${op} ${spec.where.value}`;
}
```

Refuse unknown operators. Do not copy `where.operator` into SQL unless it is in the list. `optokens` is a type, not this function.

## INSERT with `{ fn: now }`

Use this for `create.NewUser` nodes in `db/pg/user.yml`.

```ts
function buildInsert(spec: {
  insert: { into: string; columns: string[]; values: unknown[] };
}): string {
  const columns = spec.insert.columns.join(", ");
  const values = spec.insert.values
    .map((value) =>
      value && typeof value === "object" && "fn" in (value as object)
        ? "NOW()"
        : String(value),
    )
    .join(", ");
  return `INSERT INTO ${spec.insert.into} (${columns}) VALUES (${values})`;
}
```

Tighten `"NOW()"` to a known `fn` allow-list if you do not want every object to become `NOW()`.

## CREATE TABLE from mixed fields

Use this when schema YAML mixes objects and string fragments.

```ts
function columnSql(name: string, definition: unknown): string {
  if (typeof definition === "string") return `${name} ${definition}`;
  const field = definition as {
    type: string;
    length?: number;
    size?: number;
    primaryKey?: boolean;
    autoIncrement?: boolean;
    unique?: boolean;
    null?: boolean;
  };
  const width = field.length ?? field.size;
  const type = width ? `${field.type}(${width})` : field.type;
  const parts = [name, type];
  if (field.primaryKey) parts.push("PRIMARY KEY");
  if (field.autoIncrement) parts.push("GENERATED BY DEFAULT AS IDENTITY");
  if (field.unique) parts.push("UNIQUE");
  if (field.null === false) parts.push("NOT NULL");
  return parts.join(" ");
}
```

Swap identity syntax for MySQL. Nectarine will not.

## Parameterized `PgSql` unit of work

Use this for one request or script step. Check `connect` and `query`. Disconnect in `finally`.

```ts
import { PgSql } from "@citrusworx/nectarine";
import type { Client } from "pg";

async function withPg<T>(fn: (pg: PgSql, client: Client) => Promise<T>): Promise<T> {
  const db = process.env.PG_DB;
  if (!db) throw new Error("Set PG_DB");
  const pg = new PgSql();
  pg.addDb(db);
  const client = await pg.connect(db);
  if (!client) throw new Error("No Postgres client");
  try {
    return await fn(pg, client);
  } finally {
    await pg.disconnect(client);
  }
}

await withPg(async (pg, client) => {
  const result = await pg.query(client, {
    sql: "SELECT id FROM users WHERE id = $1",
    params: [1],
  });
  if (!result) throw new Error("query failed");
  return result.rows;
});
```

## Walk nested API YAML

Use this for checked-in `userAPI.yml`, which `registerRoute` cannot index.

```ts
import { parser } from "@citrusworx/nectarine";

const api = parser.yaml("./models/user/userAPI.yml");
const getAll = api.user.get.allUsers.api;
// { method: "GET", endpoint: "/users" }
```

Flatten the file if you want `registerRoute(path, "get", "allUsers")`.

## Seltzer catalog route

Use this to copy `method` + `endpoint` and run a named query in the handler.

```ts
import { parser } from "@citrusworx/nectarine";
import { Seltzer } from "@citrusworx/seltzer";

const api = parser.yaml("./models/user/api.yml");
const app = Seltzer.init();

app.route({
  method: api.get.allUsers.api.method,
  path: api.get.allUsers.api.endpoint,
  handler: async (ctx) => {
    const spec = parser.genSQL("./models/user/queries.yml", "user", "get", "AllUsers");
    const sql = buildSelect(spec);
    await withPg(async (pg, client) => {
      const result = await pg.query(client, { sql });
      if (!result) return ctx.json({ error: "query failed" }, 500);
      ctx.json({ users: result.rows });
    });
  },
});

app.listen(3000);
```

Keep paths exact. Read `?id=` from `ctx.req.url` instead of `/users/:id` until Seltzer has param routes.

## MySQL insert fragment

Use this with `db/msql/user.yml` `user.create.new`.

```ts
import { parser, Mysql, mapInsert } from "@citrusworx/nectarine";

const spec = parser.genSQL("./db/msql/user.yml", "user", "create", "new");
const columns = spec.updates.column.join(", ");
const placeholders = mapInsert(spec);
const sql = `${spec.type} ${spec.action} ${spec.table} (${columns}) ${spec.values} (${placeholders})`;

await Mysql(sql, ["ops@citrusworx.com", "hash", "Operator"]);
```

`mapInsert` only joins values. Close the pool on shutdown, not here.

## Mongo script vs server

**Script** (helper closes the client):

```ts
import { connectMngz, insertOne } from "@citrusworx/nectarine";

const client = await connectMngz();
await insertOne(client, "users", { email: "ops@citrusworx.com" });
```

**Server** (keep the client, use the driver):

```ts
import { Mngz } from "@citrusworx/nectarine";

await Mngz(async (client) => {
  const users = client.db(process.env.MG_DB).collection("users");
  await users.insertOne({ email: "ops@citrusworx.com" });
  const found = await users.find({}).toArray();
  console.log(found);
});
```

## One resource folder

Use this layout so humans and `genSQL` agree:

```text
models/user/
  schema.yml
  queries.yml      # user.get.UserById
  api.yml          # get.allUsers (flat) or walk nested
```

Do not put SELECT nodes inside the schema file and expect `genSQL` to find them.

## Pattern notes

- Prefer YAML keys you authored over request strings inside SQL.
- Prefer one DSL per engine file.
- Prefer `parser.yaml` when `registerRoute` would have to guess a resource prefix.
- Prefer throwing in *your* builder over calling empty `buildQuery`.
- Prefer checking `PgSql.query` over assuming `rows`.

## How to adapt these

Juice and Sig.js do not change these patterns. Fetch JSON from the Seltzer route; hold it in a `Signal`. Grapevine does not start the process. WebEngine does not import the package. The catalog is still parse → compile → adapter → HTTP you wired.
