# Juice Theme Authoring

## Purpose

This document explains how themes work in Juice today.

Themes define identity.

Juice defines structure.

That means a theme should answer:

- what is the brand voice?
- what are the body and heading fonts?
- what are the page, text, accent, and surface colors?
- what semantic elements should feel themed by default?
- what named surfaces should the theme expose?

Juice still owns:

- `stack`
- `row`
- `grid`
- `gap`
- `padding`
- sizing and spacing primitives
- responsive layout behavior

## Current theme model

Juice now supports two equally valid theme sources:

### 1. Library-owned themes

These live in:

```text
libraries/juice/src/themes/<id>/
```

They can be authored manually and discovered by the Juice build.

### 2. App-owned themes

These live in the consuming app, for example:

```text
apps/blackwatersound/front/juice.theme.yaml
```

They are generated by Juice into app-local artifacts such as:

```text
apps/blackwatersound/front/src/generated/blackwatersound-theme.css
apps/blackwatersound/front/src/generated/blackwatersound-theme.yaml
```

This app-owned model is now the recommended path for product-specific branding.

## Theme responsibilities

A healthy Juice theme should own:

- page atmosphere
- text and heading color relationships
- body and display font choices
- optional font-role variants
- default surface tone
- form/control tone
- named surfaces for authored brand moments

Themes should not own:

- layout primitives
- responsive rules
- app state
- feature behavior

## Required config shape

The generator currently expects a config object with at least:

```yaml
id: mytheme
name: My Theme

typography:
  body:
    family: '"noto-sans"'
    fallback: sans-serif
  heading:
    family: '"citrus-gothic"'
    fallback: sans-serif

palette:
  page:
    background: "#f4f0e8"
  text:
    default: "#211c1b"
    muted: "#6f6660"
    heading: "#211c1b"
  accents:
    primary: "#ff7716"
  surfaces:
    default: "#fffdf8"
    border: "rgba(33, 28, 27, 0.12)"
```

Optional sections:

- `selector`
- `summary`
- `philosophy`
- `recommended_use_cases`
- `authoring_rules`
- `typography.variants`
- `named_surfaces`

## Typography variants

This is a current library capability that older docs did not cover well.

Themes can define additional font roles under `typography.variants`.

Example:

```yaml
typography:
  body:
    family: '"noto-sans"'
    fallback: sans-serif
  heading:
    family: '"citrus-gothic"'
    fallback: sans-serif
  variants:
    body_condensed:
      family: '"noto-sans-condensed"'
      fallback: sans-serif
    display_shadow:
      family: '"citrus-gothic-shadow"'
      fallback: sans-serif
```

The generator emits CSS variables like:

- `--jx-body-font`
- `--jx-heading-font`
- `--jx-font-body-condensed`
- `--jx-font-display-shadow`

Juice itself does not guess how your app should use these extra roles. The app or theme-specific selectors decide that.

## Named surfaces

Themes can define named surfaces that build on Juice's structural hooks.

Example:

```yaml
named_surfaces:
  - name: bw-stage
    purpose: High-contrast marquee surface for hero moments.
    background: "linear-gradient(135deg, #111 0%, #333 100%)"
    color: "rgba(255, 255, 255, 0.92)"
    border: "rgba(255, 255, 255, 0.12)"
```

That surface can then be used in markup like:

```html
<section hero surface="bw-stage">...</section>
```

This is the right relationship:

- Juice gives you `[hero]`, `[card]`, `[panel]`, `[cta]`
- the theme gives those surfaces brand identity
- named surfaces let the theme expose specific branded recipes without inventing a parallel layout system

## Generator usage

Generate library themes:

```bash
yarn workspace @citrusworx/juiceui generate:themes
```

Generate an app-owned theme:

```bash
yarn workspace @citrusworx/juiceui generate:themes \
  --config ../../apps/blackwatersound/front/juice.theme.yaml \
  --css-out ../../apps/blackwatersound/front/src/generated/blackwatersound-theme.css \
  --yaml-out ../../apps/blackwatersound/front/src/generated/blackwatersound-theme.yaml
```

When using `--config`, `--css-out` is required. `--yaml-out` is optional but recommended when the app wants a committed generated contract alongside the CSS.

## What the generator writes

The generated stylesheet currently defines:

- page variables
- text variables
- accent variables
- surface variables
- body and heading font variables
- optional typography variant variables
- semantic defaults for elements like `section`, `article`, `nav`, `footer`, and `form`
- base treatments for `[hero]`, `[card]`, `[panel]`, `[cta]`, `[badge]`, and `[stat]`
- optional rules for `named_surfaces`

## Recommended authoring rules

- Let Juice own structure and responsiveness
- Keep the theme focused on identity
- Prefer semantic HTML before adding custom selectors
- Use named surfaces for clear branded moments, not for every block
- Treat app CSS as a light extension layer, not the primary design system

## Practical example

Blackwater Sound is the clearest current example of the modern model:

- app-owned `juice.theme.yaml`
- generated app-local theme artifacts
- Juice attributes for page structure
- app selectors for specific editorial/retail polish

That is a better long-term pattern than forcing every product theme to live inside the Juice library.
