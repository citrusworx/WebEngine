# CitrusWorx Engineering Philosophy

Creative engineering values useful craft: robust systems that remain understandable to their builders and users.

## Principles

- Build focused libraries that work independently and compose through explicit contracts.
- Prefer platform capabilities and progressively enhanced experiences over unnecessary dependencies.
- Keep coupling directional and intentional; WebEngine coordinates subsystems rather than turning every library into an engine dependency.
- Favor comprehensible code, explicit names, discoverable APIs, testable units, and minimal magic.
- Use abstractions when they remove real repetition or enforce meaningful invariants, not merely for novelty.
- Consider performance, accessibility, security, documentation, and maintenance parts of a feature.
- Distinguish shipped behavior, intended direction, and experimentation.

## When exploring an unfamiliar area

Map entry points, exports, tests, docs, consumers, package scripts, and stability gates. Keep an evidence-backed set of observations with file paths. Explain uncertainty rather than filling gaps with guesses.
